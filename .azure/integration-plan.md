# Integration hand-off

- **Application:** PHP 8+ server-rendered monolith at workspace root; `index.php` routes authenticated views and POST actions.
- **Backend run:** XAMPP Apache + MySQL, then browse `http://localhost/ERP/`. Optional syntax check: `C:\xampp\php\php.exe -l index.php` and recursively lint `app/*.php`.
- **Frontend:** same PHP application (`app/views.php`, `app/extra_views.php`); Bootstrap 5.3.3 CSS/JS and app styles are local in `public/assets/`. No separate frontend build/dev command, API seam, mock client, or mock data exists.
- **API routes:** server-rendered GET `index.php?action=setup|login|password|accounts|reports|receipt&id=...` and `index.php?module=<module>`; state-changing POST routes use CSRF fields for setup/login/logout, module save/delete, enrollment, account actions, and password changes. Modules are enumerated in `app/modules.php`.
- **Database:** MySQL/MariaDB; schema/import: `database/schema.sql`; PDO config: local ignored `config/config.php` based on `config/config.example.php`; no separate migration runner. No additional seed data should be generated by an integration phase. The approved initial schema intentionally has fictional sample records to satisfy the project plan; it contains no user accounts or credentials.
- **Data wiring:** frontend and backend are already the same live PHP/PDO application; all module views query MySQL directly. No mock files or client-side API replacement are present.
- **Services:** one local PHP/Apache + MySQL service; no external runtime dependencies. Essential scope includes identity/tenant controls, admissions, student/staff, academics, attendance, fees/receipts, exams/results, library, hostel, transport and reports.
- **Database policy:** preserve the approved schema and fictional sample records; never create seed credentials. Preserve the one-time Super Admin setup wizard and server-side role/college/parent scoping.
